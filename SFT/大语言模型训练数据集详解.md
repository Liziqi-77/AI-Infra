想象你在培养一个学生参加数学竞赛：

```

│                                                                              │

## 2. SFT冷启动训练数据集

### 2.1 数据集基本信息

| 属性 | 值 |
|------|-----|
| **数据集名称** | `hkust-nlp/drkernel-coldstart-8k` |
| **数据量** | 约8000条训练样本 |
| **训练文件** | `train_2000.parquet` (2000条用于训练) |
| **格式** | Parquet格式 |

### 2.2 数据集构成

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    SFT数据集结构                                             │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  每条数据包含两个核心字段:                                                   │
│                                                                              │
│  ┌───────────────────────────────────────────────────────────────────────┐  │
│  │ {                                                                      │  │
│  │   "prompt": "请优化以下PyTorch内核代码，使用Triton实现更高效的版本：  │  │
│  │            \n\ndef softmax(x):                                        │  │
│  │            \n    return torch.softmax(x, dim=-1)",                    │  │
│  │                                                                        │  │
│  │   "response": "这是优化后的Triton内核实现：                           │  │
│  │               \nimport triton                                         │  │
│  │               \nimport triton.language as tl                          │  │
│  │               \n                                                      │  │
│  │               \n@triton.jit                                           │  │
│  │               \ndef softmax_kernel(...):                              │  │
│  │               \n    # 高效的Triton实现                                │  │
│  │               \n    ..."                                              │  │
│  │ }                                                                      │  │
│  └───────────────────────────────────────────────────────────────────────┘  │
│                                                                              │
│  字段说明:                                                                   │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │ • prompt:    问题描述，包含需要优化的原始代码                        │   │
│  │ • response:  标准答案，包含高质量的优化后代码                        │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 2.3 数据来源与特点

**数据来源:**
```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        SFT数据来源                                           │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  1. 高质量人工标注                                                          │
│     ┌─────────────────────────────────────────────────────────────────┐    │
│     │ • 由GPU内核优化专家编写标准答案                                  │    │
│     │ • 确保代码正确性、高效性                                        │    │
│     │ • 覆盖常见的内核优化场景                                        │    │
│     └─────────────────────────────────────────────────────────────────┘    │
│                                                                              │
│  2. 多样化任务覆盖                                                          │
│     ┌─────────────────────────────────────────────────────────────────┐    │
│     │ • Softmax、LayerNorm、GELU等常见算子                             │    │
│     │ • 矩阵乘法、卷积等计算密集型操作                                 │    │
│     │ • 不同输入尺寸和配置                                             │    │
│     └─────────────────────────────────────────────────────────────────┘    │
│                                                                              │
│  3. 数据质量保证                                                            │
│     ┌─────────────────────────────────────────────────────────────────┐    │
│     │ • 所有代码经过编译验证                                          │    │
│     │ • 所有代码经过正确性测试                                        │    │
│     │ • 所有代码经过性能基准测试                                      │    │
│     └─────────────────────────────────────────────────────────────────┘    │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

**数据特点:**

| 特点 | 说明 |
|------|------|
| **高质量** | 每条答案都经过验证，确保正确且高效 |
| **格式统一** | 采用统一的prompt-response格式 |
| **覆盖全面** | 涵盖GPU内核优化的常见场景 |
| **难度适中** | 适合模型学习基本技能 |

### 2.4 为什么需要SFT冷启动？

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    SFT冷启动的必要性                                         │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  问题: 预训练模型能直接用于RL训练吗？                                        │
│                                                                              │
│  ┌───────────────────────────────────────────────────────────────────────┐  │
│  │                                                                        │  │
│  │  预训练模型 (如Qwen2.5-7B) 的问题:                                    │  │
│  │                                                                        │  │
│  │  1. 不懂任务格式                                                      │  │
│  │     • 不知道什么是"内核优化任务"                                      │  │
│  │     • 不知道应该如何组织回答                                          │  │
│  │     • 可能输出与任务无关的内容                                        │  │
│  │                                                                        │  │
│  │  2. 缺乏专业领域知识                                                  │  │
│  │     • 不了解Triton语法                                                │  │
│  │     • 不了解GPU编程范式                                               │  │
│  │     • 不了解性能优化技巧                                              │  │
│  │                                                                        │  │
│  │  3. RL训练效率极低                                                    │  │
│  │     • 如果模型连基本代码都不会写                                      │  │
│  │     • RL的奖励信号几乎全是负的                                        │  │
│  │     • 模型很难学到有效策略                                            │  │
│  │                                                                        │  │
│  └───────────────────────────────────────────────────────────────────────┘  │
│                                                                              │
│  解决方案: SFT冷启动                                                        │
│  ┌───────────────────────────────────────────────────────────────────────┐  │
│  │                                                                        │  │
│  │  通过SFT训练，让模型:                                                 │  │
│  │                                                                        │  │
│  │  ✓ 学会任务格式 - 知道如何回答内核优化问题                            │  │
│  │  ✓ 掌握基础知识 - 学会Triton语法和GPU编程                             │  │
│  │  ✓ 具备初始能力 - 能生成可编译、正确的代码                            │  │
│  │  ✓ 提高RL效率 - RL阶段可以从"优化"而非"学习"开始                      │  │
│  │                                                                        │  │
│  └───────────────────────────────────────────────────────────────────────┘  │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 2.5 SFT在模型初始化中的关键作用

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    SFT的作用: 从"不会"到"会"                                 │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  预训练模型输出 (SFT之前):                                                   │
│  ┌───────────────────────────────────────────────────────────────────────┐  │
│  │ Prompt: "请优化这个softmax函数..."                                    │  │
│  │                                                                        │  │
│  │ 输出: "softmax是一个常用的激活函数，它可以将输入转换为概率分布。      │  │
│  │        在深度学习中，softmax常用于多分类问题的输出层..."              │  │
│  │                                                                        │  │
│  │ 问题: 输出的是概念解释，而非代码实现！                                │  │
│  └───────────────────────────────────────────────────────────────────────┘  │
│                                                                              │
│                              ▼ SFT训练后                                     │
│                                                                              │
│  SFT模型输出 (SFT之后):                                                      │
│  ┌───────────────────────────────────────────────────────────────────────┐  │
│  │ Prompt: "请优化这个softmax函数..."                                    │  │
│  │                                                                        │  │
│  │ 输出: "import triton                                                  │  │
│  │        import triton.language as tl                                   │  │
│  │                                                                        │  │
│  │        @triton.jit                                                    │  │
│  │        def softmax_kernel(x_ptr, out_ptr, N, BLOCK: tl.constexpr):    │  │
│  │            # Triton内核实现                                           │  │
│  │            ..."                                                       │  │
│  │                                                                        │  │
│  │ 改进: 输出的是可编译的Triton代码！                                    │  │
│  └───────────────────────────────────────────────────────────────────────┘  │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    RL数据集结构                                              │

│                                                                              │

│  │ {                                                                      │  │
│  │   "id": "kernel_001",                                                  │  │
│  │                                                                        │  │
│  │   "prompt": "请优化以下PyTorch内核代码：                              │  │

│  │                                                                        │  │

│  │                     \n    return torch.layer_norm(x, ...)",           │  │
│  │                                                                        │  │
│  │   "test_inputs": {                                                     │  │
│  │     "x": "随机生成的测试输入张量",                                    │  │
│  │     "weight": "权重参数",                                              │  │
│  │     "bias": "偏置参数"                                                 │  │
│  │   },                                                                   │  │
│  │                                                                        │  │
│  │   "metadata": {                                                        │  │
│  │     "difficulty": "medium",                                            │  │

│  │ }                                                                      │  │

│                                                                              │
│  字段说明:                                                                   │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │ • id:            任务唯一标识                                        │   │
│  │ • prompt:        问题描述（模型需要生成答案）                        │   │
│  │ • reference_code: 参考实现（用于正确性对比）                         │   │
│  │ • test_inputs:   测试输入数据（用于验证正确性）                      │   │
│  │ • metadata:      任务元信息                                          │   │
│  │                                                                        │   │
│  │ 注意: 没有"response"字段！模型需要自己生成答案。                     │   │

│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 3.4 RL数据收集方法

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    RL数据收集流程                                            │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  1. 从KernelBench基准收集                                                   │

### 5.3 评测集的评估指标

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    评测集评估指标体系                                        │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  1. 编译成功率 (Compilation Rate)                                           │
│     ┌─────────────────────────────────────────────────────────────────┐    │
│     │ 定义: 成功编译的代码数 / 总提交数                                │    │
│     │ 意义: 模型能否生成语法正确的代码                                 │    │

│     └─────────────────────────────────────────────────────────────────┘    │
│                                                                              │
│  2. 正确性通过率 (Correctness Rate)                                         │
│     ┌─────────────────────────────────────────────────────────────────┐    │
│     │ 定义: 输出正确的代码数 / 编译成功数                              │    │
│     │ 意义: 模型生成的代码是否功能正确                                 │    │
│     │ 示例: 92% 表示编译通过的代码中92%是正确的                        │    │
│     └─────────────────────────────────────────────────────────────────┘    │
│                                                                              │
│  3. 平均加速比 (Average Speedup)                                            │
│     ┌─────────────────────────────────────────────────────────────────┐    │
│     │ 定义: 参考实现时间 / 优化后时间 的平均值                         │    │
│     │ 意义: 模型生成的代码性能提升程度                                 │    │
│     │ 示例: 2.5x 表示优化后代码平均快2.5倍                             │    │
│     └─────────────────────────────────────────────────────────────────┘    │
│                                                                              │
│  4. Pass@k 指标                                                             │
│     ┌─────────────────────────────────────────────────────────────────┐    │
│     │ 定义: k次尝试中至少成功一次的概率                                │    │
│     │ 意义: 模型生成多个候选时的成功率                                 │    │
│     │ 示例: Pass@8 = 85% 表示生成8个代码有85%概率至少一个正确          │    │
│     └─────────────────────────────────────────────────────────────────┘    │
│                                                                              │
│  5. 覆盖率 (Coverage)                                                       │
│     ┌─────────────────────────────────────────────────────────────────┐    │
│     │ 定义: 自定义内核执行时间 / 总执行时间                            │    │
│     │ 意义: 模型是否真正优化了核心计算                                 │    │
│     │ 示例: 45% 表示45%的计算使用了自定义内核                          │    │
│     └─────────────────────────────────────────────────────────────────┘    │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

| **使用阶段** | SFT训练 | RL训练 | RL训练 | 训练后评估 |
| **使用目的** | 学习基本技能 | 学习优化策略 | 监控训练效果 | 最终性能评估 |
| **是否影响训练** | 直接影响 | 直接影响 | 间接影响 | 不影响 |
| **数据量** | 中等(~8k) | 大量 | 较小 | 中等 |
| **类比** | 教材例题 | 练习题 | 模拟考试 | 正式考试 |

### 6.3 关键要点总结

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          关键要点                                            │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  1. SFT数据集 = "教材"                                                      │
│     • 包含标准答案，让模型学会基本技能                                       │
│     • 没有SFT，模型不知道如何回答问题                                       │
│     • 是RL训练的基础                                                        │
│                                                                              │
│  2. RL数据集 = "练习题"                                                     │
│     • 只有问题，没有标准答案                                                 │
│     • 模型通过试错学习优化策略                                               │
│     • KernelGYM提供客观的奖励反馈                                           │
│                                                                              │
│  3. 验证集 = "模拟考试"                                                     │
│     • 用于监控训练过程                                                       │
│     • 帮助选择最佳模型和超参数                                               │
│     • 防止过拟合                                                             │
│                                                                              │
│  4. 评测集 = "正式考试"                                                     │
│     • 训练过程中绝对不能使用                                                 │
│     • 用于客观评估最终性能                                                   │
│     • 是论文报告和模型对比的依据                                             │
│                                                                              │
│  5. 数据隔离原则                                                            │
│     • 评测集数据不能出现在训练集或验证集中                                   │
│     • 否则评估结果不可信，相当于"泄题"                                      │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```
