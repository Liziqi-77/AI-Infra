# 核心概念详解

本文档详细介绍 rLLM 框架中的核心数据类型和概念。理解这些概念是掌握 rLLM 的基础。

## 数据层次结构

rLLM 使用四层数据结构来组织训练数据，从最小到最大依次为：

```
Step → Trajectory → Episode / TrajectoryGroup
```

```
Episode（一个任务的完整结果）
├── Trajectory 1（Agent 的一次运行）
│   ├── Step 1（一次 LLM 调用）
│   │   ├── prompt_ids: [101, 2054, ...]    # 输入 token IDs
│   │   ├── response_ids: [345, 678, ...]   # 输出 token IDs
│   │   ├── logprobs: [-0.5, -0.3, ...]     # 每个 token 的对数概率
│   │   ├── thought: "让我想想..."           # 模型的思考过程
│   │   ├── action: Action(...)             # 采取的动作
│   │   ├── reward: 0.0                     # 该步的奖励
│   │   ├── advantage: 0.5                  # 优势值（用于 RL）
│   │   └── ...
│   └── Step 2
│       └── ...
├── Trajectory 2
└── ...
```

## 1. Step（步骤）

`Step` 是 rLLM 中最基本的数据单元，表示**一次 LLM 调用**的完整信息。

### 1.1 基础版 Step（rllm/types.py）

这是轻量级的基础版本，SDK 直接使用这个版本：

```python
class Step(BaseModel):
    """A single interaction step (one LLM call with optional reward)."""
    
    id: str = Field(default_factory=lambda: str(uuid.uuid4()))  # 唯一标识
    input: Any | None = None          # 输入内容
    output: Any | None = None         # 输出内容
    action: Any | None = None         # 采取的动作
    reward: float = 0.0               # 该步获得的奖励
    done: bool = False                # 是否结束
    metadata: dict | None = None      # 额外元数据
```

### 1.2 训练版 Step（rllm/agents/agent.py）

训练时使用的扩展版本，包含了 RL 训练必需的字段：

```python
class Step(_StepBase):
    """Training step with token IDs, logprobs, advantage."""
    
    # === 训练必需字段 ===
    prompt_ids: list[int] = []        # 输入 prompt 的 token IDs
    response_ids: list[int] = []      # 模型生成的 token IDs
    logprobs: list[float] = []        # 每个生成 token 的对数概率
    routing_matrices: list[str] | None = None  # 路由矩阵（MoE 模型用）
    
    # === 对话历史 ===
    chat_completions: list[dict] = []  # 完整的对话历史（OpenAI 格式）
    
    # === Agent 状态 ===
    observation: Any = None           # 环境观察
    thought: str = ""                 # 模型的思考/推理过程
    action: Action = None             # 采取的动作
    model_response: str = ""          # 模型的文本响应
    model_output: ModelOutput | None  # 完整的模型输出对象
    
    # === RL 相关 ===
    reward: float = 0.0               # 该步奖励
    done: bool = False                # 是否结束
    mc_return: float = 0.0            # Monte Carlo 回报（折扣累积奖励）
    advantage: list[float] | float | None = None  # 优势值
    
    # === 异步训练 ===
    weight_version: int | None = None  # 生成时使用的模型权重版本
```

### 1.3 Step 关键字段详解

| 字段 | 类型 | 说明 |
|------|------|------|
| `prompt_ids` | `list[int]` | 输入文本经过 tokenizer 后的 token ID 序列，用于策略梯度计算 |
| `response_ids` | `list[int]` | 模型生成的 token ID 序列，与 logprobs 一一对应 |
| `logprobs` | `list[float]` | 每个生成 token 的对数概率，RL 算法计算策略梯度的关键数据 |
| `chat_completions` | `list[dict]` | 完整的对话历史，格式与 OpenAI API 一致 |
| `thought` | `str` | 模型的推理/思考过程（如 `<think>...</think>` 标签内的内容） |
| `advantage` | `float` | 优势值 A(s,a) = Q(s,a) - V(s)，衡量动作相对于平均表现的好坏 |
| `mc_return` | `float` | Monte Carlo 回报，从当前步到结束的折扣累积奖励 |
| `weight_version` | `int` | 异步训练中追踪模型版本，用于判断数据是否过期 |

### 1.4 Step 的创建方式

**方式一：从 ModelOutput 创建**

```python
step = Step.from_model_output(
    model_output=model_output,  # RolloutEngine 的输出
    messages=[{"role": "user", "content": "你好"}],  # 输入消息
    action=Action(action="回答"),
)
```

**方式二：从字典反序列化**

```python
step = Step.from_dict({
    "prompt_ids": [101, 2054, ...],
    "response_ids": [345, 678, ...],
    "logprobs": [-0.5, -0.3, ...],
    "chat_completions": [...],
    "observation": "...",
    "thought": "...",
    "action": "...",
    "model_response": "...",
    "model_output": {...},
    "reward": 1.0,
    "done": False,
    "mc_return": 1.0,
    "advantage": 0.5,
})
```

**方式三：手动创建**

```python
step = Step(
    prompt_ids=[101, 2054],
    response_ids=[345, 678],
    logprobs=[-0.5, -0.3],
    chat_completions=[{"role": "user", "content": "你好"}, {"role": "assistant", "content": "你好！"}],
    thought="用户打招呼，我应该礼貌回应",
    action=Action(action="你好！"),
    model_response="你好！",
    reward=0.0,
    done=False,
)
```

### 1.5 Step 的序列化

```python
# 序列化为字典
step_dict = step.to_dict()

# 从字典反序列化
step = Step.from_dict(step_dict)
```

## 2. Trajectory（轨迹）

`Trajectory` 表示**一次完整的 Agent 运行**，由多个 Step 组成。

### 2.1 基础版 Trajectory（rllm/types.py）

```python
class Trajectory(BaseModel):
    """A sequence of Steps forming one agent trajectory."""
    
    uid: str = Field(default_factory=lambda: str(uuid.uuid4()))  # 唯一标识
    name: str = "agent"           # 轨迹名称（如 "solver", "judge"）
    task: Any = None              # 任务描述
    steps: list[Step] = []        # 步骤列表
    reward: float | None = None   # 轨迹总奖励
    input: dict | None = None     # 函数输入参数（SDK 用）
    output: Any = None            # 函数返回值（SDK 用）
    signals: dict[str, float] = {} # 评估信号
    metadata: dict | None = None  # 额外元数据
    
    @property
    def result(self):
        """获取输出（向后兼容）"""
        return self.output
```

### 2.2 训练版 Trajectory（rllm/agents/agent.py）

```python
class Trajectory(_TrajectoryBase):
    """Training trajectory extending the canonical Trajectory."""
    
    name: str = "default_traj_name"       # 覆盖默认名称
    steps: list[Step] = []                # 训练 Step 列表
    
    @property
    def info(self) -> dict:
        """metadata 的别名"""
        if self.metadata is None:
            self.metadata = {}
        return self.metadata
```

### 2.3 Trajectory 关键字段详解

| 字段 | 类型 | 说明 |
|------|------|------|
| `uid` | `str` | 全局唯一标识符，用于去重和追踪 |
| `name` | `str` | 轨迹名称，在多 Agent 场景中标识是哪个 Agent 的轨迹 |
| `task` | `Any` | 任务描述，通常是包含问题、答案等信息的字典 |
| `steps` | `list[Step]` | 按时间顺序排列的步骤列表 |
| `reward` | `float` | 轨迹级别的总奖励（通常是所有 step.reward 的和） |

### 2.4 重要方法

**判断是否为累积型轨迹**

```python
is_cumulative = trajectory.is_cumulative()
```

累积型轨迹指的是：每一步的 `chat_completions` 都是前一步的超集（即对话历史不断增长）。这在多轮对话中很常见。

**序列化**

```python
# 序列化（会自动清理 image 等大字段）
traj_dict = trajectory.to_dict()

# 反序列化
trajectory = Trajectory.from_dict(traj_dict)
```

## 3. Episode（回合）

`Episode` 表示**一个任务的完整结果**，可以包含一个或多个 Trajectory。

### 3.1 基础版 Episode（rllm/types.py）

```python
class Episode(BaseModel):
    """A rollout episode containing one or more Trajectories."""
    
    id: str = Field(default_factory=lambda: str(uuid.uuid4()))  # 唯一标识
    task: Any = None                    # 任务描述
    termination_reason: Any | None = None  # 终止原因
    is_correct: bool = False            # 是否正确
    trajectories: list[Trajectory] = [] # 轨迹列表
    artifacts: dict[str, Any] = {}      # 产物（如生成的代码、答案）
    metrics: dict = {}                  # 指标
    metadata: dict = {}                 # 元数据
    
    @property
    def task_id(self) -> str:
        """从 id 中提取任务 ID（格式为 "task_id:rollout_idx"）"""
        return self.id.split(":")[0]
    
    @property
    def rollout_idx(self) -> str:
        """从 id 中提取 rollout 索引"""
        return self.id.split(":")[1]
```

### 3.2 训练版 Episode（rllm/agents/agent.py）

```python
class Episode(_EpisodeBase):
    """Training episode extending the canonical Episode."""
    
    trajectories: list[Trajectory] = []  # 训练 Trajectory 列表
    
    @property
    def info(self) -> dict:
        """metadata 的别名"""
        return self.metadata
```

### 3.3 Episode 关键字段详解

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `str` | 格式为 `"task_id:rollout_idx"`，如 `"gsm8k_001:0"` |
| `task` | `Any` | 任务数据，通常包含问题、标准答案等 |
| `termination_reason` | `TerminationReason` | 终止原因枚举值 |
| `is_correct` | `bool` | 该任务是否被正确解决 |
| `trajectories` | `list[Trajectory]` | 包含的轨迹列表 |
| `artifacts` | `dict` | 任务产物，如生成的代码、最终答案等 |
| `metrics` | `dict` | 评估指标，如 `{"default_traj_name_acc": 0.8}` |

### 3.4 终止原因（TerminationReason）

```python
class TerminationReason(Enum):
    MAX_PROMPT_LENGTH_EXCEEDED = "max_prompt_length_exceeded"   # prompt 超长
    MAX_RESPONSE_LENGTH_EXCEEDED = "max_response_length_exceeded"  # 响应超长
    ENV_DONE = "env_done"           # 环境标记完成
    MAX_TURNS_EXCEEDED = "max_turns_exceeded"  # 超过最大轮数
    TIMEOUT = "timeout"             # 超时
    UNKNOWN = "unknown"             # 未知原因
    ERROR = "error"                 # 发生错误
```

### 3.5 序列化

```python
# 序列化
episode_dict = episode.to_dict()

# 反序列化
episode = Episode.from_dict(episode_dict)
```

## 4. TrajectoryGroup（轨迹组）

`TrajectoryGroup` 是**专门用于优势计算**的 Trajectory 分组。与 Episode 不同，Episode 表示原始 rollout 数据，而 TrajectoryGroup 的结构专门为 GRPO 等算法的优势计算而设计。

```python
class TrajectoryGroup(BaseModel):
    """A group of trajectories for advantage computation."""
    
    trajectories: list[Trajectory]   # 用于比较的轨迹列表
    group_id: str = ""               # 组标识符（如 "task1:agent_0"）
    metadata: list[dict] = []        # 每个轨迹的元数据
    weight_version: int = 0          # 权重版本
    
    @property
    def group_role(self) -> str:
        """获取组角色"""
        return self.group_id.split(":")[1] if ":" in self.group_id[:-1] else "all_groups"
    
    @property
    def task_id(self) -> str:
        """获取任务 ID"""
        return self.group_id.split(":")[0]
```

### 4.1 为什么需要 TrajectoryGroup？

在 GRPO（Group Relative Policy Optimization）算法中，需要对**同一任务的多个 rollout 结果**进行比较，计算每个结果的相对优势。TrajectoryGroup 就是用来组织这些数据的：

```
TrajectoryGroup（同一任务的多个 rollout）
├── Trajectory 1（第 1 次 rollout，reward = 0.8）
├── Trajectory 2（第 2 次 rollout，reward = 0.6）
├── Trajectory 3（第 3 次 rollout，reward = 1.0）
└── Trajectory 4（第 4 次 rollout，reward = 0.4）

优势计算：
- mean_reward = (0.8 + 0.6 + 1.0 + 0.4) / 4 = 0.7
- Trajectory 1 advantage = 0.8 - 0.7 = 0.1
- Trajectory 2 advantage = 0.6 - 0.7 = -0.1
- Trajectory 3 advantage = 1.0 - 0.7 = 0.3
- Trajectory 4 advantage = 0.4 - 0.7 = -0.3
```

## 5. Action（动作）

`Action` 是一个简单的包装类，表示 Agent 采取的动作：

```python
class Action(BaseModel):
    action: Any = None
```

在实际使用中，`action` 可以是：
- 一个字符串（如 "你好！"）
- 一个工具调用（`ToolCall` 对象）
- 一个字典（包含多个动作信息）

## 6. ModelOutput（模型输出）

`ModelOutput` 是 RolloutEngine 返回的标准化输出：

```python
@dataclass
class ModelOutput:
    text: str | None = None                  # 纯文本输出
    content: str | None = None               # 主要内容
    reasoning: str | None = None             # 推理/思考内容
    tool_calls: list | None = None           # 工具调用列表
    prompt_ids: list[int] | None = None      # prompt token IDs
    completion_ids: list[int] | None = None  # 生成 token IDs
    logprobs: list[float] | None = None      # 对数概率
    routing_matrices: list | None = None     # 路由矩阵（MoE）
    weight_version: int | None = None        # 权重版本
    
    def to_dict(self) -> dict: ...
    @classmethod
    def from_dict(cls, data: dict) -> "ModelOutput": ...
```

## 7. 数据流示例

以下是一个完整的数据流示例，展示数据如何在各层之间传递：

```python
# 1. RolloutEngine 生成 ModelOutput
model_output = ModelOutput(
    content="答案是 42",
    reasoning="让我计算一下...",
    prompt_ids=[101, 2054, ...],
    completion_ids=[345, 678, ...],
    logprobs=[-0.5, -0.3, ...],
)

# 2. 从 ModelOutput 创建 Step
step = Step.from_model_output(
    model_output=model_output,
    messages=[{"role": "user", "content": "1+1=?"}],
)

# 3. 将 Step 添加到 Trajectory
trajectory = Trajectory(
    name="solver",
    task={"question": "1+1=?"},
    steps=[step],
)

# 4. 将 Trajectory 包装为 Episode
episode = Episode(
    task={"question": "1+1=?", "answer": "2"},
    trajectories=[trajectory],
    artifacts={"answer": "42"},
)

# 5. 计算奖励和正确性
episode.is_correct = (episode.artifacts["answer"] == "2")  # False
```

## 9. 常见使用场景

### 9.1 在 Rollout 函数中创建 Episode

```python
@rllm.rollout
def solve(task: Task, config: AgentConfig) -> Episode:
    client = OpenAI(base_url=config.base_url, api_key="EMPTY")
    
    # 调用 LLM
    response = client.chat.completions.create(
        model=config.model,
        messages=[{"role": "user", "content": task.data["question"]}],
    )
    
    answer = response.choices[0].message.content or ""
    
    # 返回 Episode
    return Episode(
        trajectories=[Trajectory(name="solver", steps=[])],
        artifacts={"answer": answer},
    )
```

### 9.2 在 Workflow 中收集 Trajectory

```python
class MyWorkflow(Workflow):
    async def run(self, task: dict, uid: str, **kwargs):
        # 重置工作流
        self.reset(task, uid)
        
        # 与环境和模型交互
        for _ in range(max_turns):
            observation = self.env.get_observation()
            model_output = await self.rollout_engine.generate(...)
            step = Step.from_model_output(model_output)
            self.agent.trajectory.steps.append(step)
            
        # 提交轨迹
        self.commit(name="solver", agent=self.agent)
        
        # 收集并返回 Episode
        return self.collect_trajectories()
```

### 9.3 在 Evaluator 中使用 Episode

```python
@rllm.evaluator
def score(task: dict, episode: Episode) -> EvalOutput:
    # 从 episode 中提取答案
    answer = episode.artifacts.get("answer", "")
    ground_truth = task["ground_truth"]
    
    # 计算奖励
    is_correct = answer.strip() == ground_truth.strip()
    reward = 1.0 if is_correct else 0.0
    
    return EvalOutput(
        reward=reward,
        is_correct=is_correct,
        signals=[Signal(name="accuracy", value=reward)],
    )
```

## 10. 总结

| 概念 | 层级 | 作用 |
|------|------|------|
| `Step` | 最底层 | 表示一次 LLM 调用，包含 token IDs、logprobs 等训练必需数据 |
| `Trajectory` | 中间层 | 表示一次完整的 Agent 运行，由多个 Step 组成 |
| `Episode` | 最高层 | 表示一个任务的完整结果，可包含多个 Trajectory |
| `TrajectoryGroup` | 特殊层 | 专门为优势计算设计的 Trajectory 分组 |
| `Action` | 辅助类 | 包装 Agent 采取的动作 |
| `ModelOutput` | 辅助类 | RolloutEngine 的标准化输出 |

理解这些核心概念后，你就可以开始学习 rLLM 的各个模块了。
