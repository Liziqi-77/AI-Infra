# rLLM 框架概述

## 什么是 rLLM？

rLLM 是一个开源的**强化学习（Reinforcement Learning, RL）训练 AI Agent 的框架**。它的核心理念是：

> **用任何 Agent 框架编写你的 AI 程序，只需极少的代码改动，就能用 RL 来训练它。**

rLLM 由 Berkeley Sky Computing Lab 开发，支持多种 Agent 框架（LangGraph、SmolAgent、Strands、OpenAI Agents SDK、Google ADK 等），也支持最基础的 `openai.OpenAI` 调用。

## 核心理念

rLLM 遵循一个简洁的训练流水线：

```
运行你的 Agent → 自动收集 Traces → 计算 Rewards → 更新模型权重
```

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  Your Agent  │───▶│    Traces     │───▶│   Rewards    │───▶│  RL Update   │
│  (any code)  │    │  (auto-logged)│    │ (your logic) │    │  (GRPO etc.) │
└──────────────┘    └──────────────┘    └──────────────┘    └──────────────┘
```

**关键特性：**
- Agent 代码几乎不需要修改
- rLLM 的 SDK 自动拦截 LLM 调用并结构化数据
- 同一套 Agent 代码可以同时用于评估（eval）和训练（train）
- 支持多种 RL 算法：GRPO、REINFORCE、RLOO、拒绝采样等
- 两种训练后端：`verl`（分布式多 GPU）和 `tinker`（单机/CPU）

## 为什么要用 rLLM？

### 传统方法的问题

在 rLLM 之前，用 RL 训练 LLM Agent 通常需要：
1. 重写 Agent 代码以适配特定的训练框架
2. 手动收集 token IDs、logprobs 等训练必需的数据
3. 为训练和评估编写两套不同的代码
4. 处理复杂的分布式训练基础设施

### rLLM 的解决方案

rLLM 通过以下方式解决了这些问题：

1. **零侵入式 Trace 收集**：通过 SDK 自动拦截 LLM 调用，无需修改 Agent 逻辑
2. **统一的数据结构**：`Step` → `Trajectory` → `Episode` 三层数据模型
3. **一套代码，两种用途**：同一个 Agent 函数既可用于评估也可用于训练
4. **开箱即用的训练基础设施**：内置 verl 和 tinker 两种后端

## 两种训练范式

rLLM 支持两种训练范式：

### 1. Agent/Environment 范式（传统方式）

```python
# 定义自定义 Agent 和 Environment
class MyAgent(BaseAgent): ...
class MyEnv(BaseEnv): ...

# 使用 AgentTrainer 训练
trainer = AgentTrainer(
    agent_class=MyAgent,
    env_class=MyEnv,
    backend="verl",
)
trainer.train()
```

这种方式类似于传统的 Gym 环境 + Agent 的 RL 训练模式。

### 2. Workflow 范式（现代方式）

```python
# 定义 Workflow 类，内部包含 Agent 和 Environment
class MyWorkflow(Workflow):
    async def run(self, task, uid, **kwargs):
        # 自定义工作流逻辑
        ...

# 使用 AgentTrainer 训练
trainer = AgentTrainer(
    workflow_class=MyWorkflow,
    backend="verl",
)
trainer.train()
```

这种方式更加灵活，适合复杂的多 Agent、多步骤场景。

### 3. SDK + Decorator 范式（最简方式）

```python
@rllm.rollout
def solve(task: Task, config: AgentConfig) -> Episode:
    client = OpenAI(base_url=config.base_url, api_key="EMPTY")
    response = client.chat.completions.create(...)
    return Episode(trajectories=[Trajectory(...)])

@rllm.evaluator
def score(task: dict, episode: Episode) -> EvalOutput:
    return EvalOutput(reward=1.0 if correct else 0.0)

trainer = AgentTrainer(
    backend="tinker",
    agent_flow=solve,
    evaluator=score,
)
trainer.train()
```

这是最简洁的方式，只需定义两个函数即可开始训练。

## 数据层次结构

rLLM 使用三层数据结构来组织训练数据：

```
Episode（一个任务）
├── Trajectory 1（一次 Agent 运行）
│   ├── Step 1（一次 LLM 调用）
│   ├── Step 2
│   └── ...
├── Trajectory 2
└── ...
```

- **Step**：表示一次 LLM 调用，包含输入、输出、token IDs、logprobs 等
- **Trajectory**：表示一次完整的 Agent 运行，由多个 Step 组成
- **Episode**：表示一个任务的完整结果，可以包含多个 Trajectory（用于优势计算）
- **TrajectoryGroup**：专门用于优势计算（如 GRPO）的 Trajectory 分组

## 两种训练后端

### Verl 后端

- **适用场景**：分布式多 GPU 训练
- **技术栈**：Ray（分布式调度）+ vLLM/SGLang（推理）
- **特点**：支持大规模并行训练，适合生产环境

### Tinker 后端

- **适用场景**：单机/CPU 训练
- **特点**：设置简单，适合快速原型开发和小规模实验

两种后端使用相同的 API，只需更改 `backend` 参数即可切换。

## 核心概念速览

| 概念 | 说明 |
|------|------|
| **Agent** | AI 代理，负责接收观察、生成动作 |
| **Environment** | 环境，提供观察、执行动作、返回奖励 |
| **Workflow** | 工作流，编排 Agent 和 Environment 的执行逻辑 |
| **Engine** | 引擎，负责模型推理和执行调度 |
| **Tool** | 工具，Agent 可以调用的外部功能（如代码执行、搜索） |
| **Reward** | 奖励函数，评估 Agent 表现 |
| **Trainer** | 训练器，协调整个 RL 训练过程 |
| **SDK** | 开发工具包，自动收集 LLM 调用信息 |
