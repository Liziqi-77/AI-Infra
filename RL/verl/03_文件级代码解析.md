**关键算法实现**：

1. **端口冲突检测与自动递增**（L39-L63）：
   ```bash
   is_port_in_use() {
     local port=$1
     if command -v lsof >/dev/null 2>&1; then
       lsof -iTCP:$port -sTCP:LISTEN -t
     elif command -v ss >/dev/null 2>&1; then
       ss -ltn | awk '{print $4}' | grep -E "[.:]$port$"
     else
       netstat -tuln 2>/dev/null | awk '{print $4}' | grep -E "[.:]$port$"
     fi
   }
   # 使用三级检测策略（lsof → ss → netstat），自动递增直到找到空闲端口
   ```
   这保证了在多个训练任务同时运行时不会端口冲突。

2. **运行名后缀自动生成**（L99-L135）：
   `generate_suffix()` 函数遍历所有命令行参数，将非默认参数拼接到运行名后，如 `_batch256_lr2e-5`。这确保每个不同的训练配置都有唯一的运行名，方便 Wandb 追踪和检查点管理。

3. **参数解析器**（L68-L93）：
   支持 17 个可覆盖的命令行参数，使用标准的 `--key value` 格式。

4. **torchrun 启动命令**（L178-L206）：
   将所有 Shell 变量以 Hydra 点号分隔的语法（如 `data.train_batch_size=$TRAIN_BATCH_SIZE`）传递给 Python 训练进程。

## 4. 数据层

### 4.1 [verl_patch/utils/dataset/sft_dataset.py](file:///c:/lzq/分享/KernelGYM/drkernel/verl_patch/utils/dataset/sft_dataset.py) (219 行)

**文件功能描述**：内存型 SFT（Supervised Fine-Tuning）数据集类，负责从 Parquet 文件或 HuggingFace datasets 加载训练数据，将 prompt 和 response 应用 Chat Template 后进行 tokenization，并生成 `loss_mask`（只对 response 部分计算 loss）。

**核心类**：
- `SFTDataset(Dataset)`：继承 `torch.utils.data.Dataset`，实现全内存数据加载。

**核心变量定义**：

| 变量 | 类型 | 含义 |
|------|------|------|
| `parquet_files` | `str` / `List[str]` | Parquet 数据文件路径（可能是目录或文件列表） |
| `tokenizer` | `PreTrainedTokenizer` | HuggingFace Tokenizer 实例 |
| `prompt_key` | `list[str]` | Parquet 中 prompt 字段的列名列表 |
| `response_key` | `list[str]` | Parquet 中 response 字段的列名列表 |
| `prompt_dict_keys` | `list[str]` | 若 prompt 列是嵌套结构，指定子键路径 |
| `response_dict_keys` | `list[str]` | 若 response 列是嵌套结构，指定子键路径 |
| `max_length` | `int` | 最大序列长度（token 数） |
| `truncation` | `str` | 截断策略（`"error"` / `"left"` / `"right"`） |
| `prompts` | `list[str]` | 所有 prompt 字符串列表 |
| `responses` | `list[str]` | 所有 response 字符串列表 |
| `dataframe` | `pd.DataFrame` | 原始 Parquet 数据 DataFrame |
| `use_hf_load` | `bool` | 是否使用 HuggingFace `datasets.load_dataset` 加载 |

**关键算法实现**：

1. **`_download()` 方法**（L72-L74）：
   ```python
   def _download(self):
       for i, parquet_file in enumerate(self.parquet_files):
           self.parquet_files[i] = copy_to_local(parquet_file, verbose=True)
   ```
   将远程 Parquet 文件（可能位于 HDFS 或 HuggingFace Hub）复制到本地缓存以加速后续读取。

2. **`_read_files_and_tokenize()` 方法**（L76-L139）：
   支持两种数据加载模式：
   
   **HuggingFace 模式** (`use_hf_load=True`)：
   ```python
   ds = load_dataset(self.parquet_files)  # 从 HuggingFace Hub 加载
   # 提取 "conversations" 字段，要求恰好2轮对话（用户+助手）
   train_pairs = ds["train"].map(get_pair, ...)
   ```
   
   **Parquet 模式** (`use_hf_load=False`)：
   ```python
   dataframe = pd.read_parquet(parquet_file)  # Pandas 读取
   self.prompts = dataframe[prompt_key].apply(series_to_item).tolist()
   self.responses = dataframe[response_key].apply(series_to_item).tolist()
   ```
   `series_to_item()` 函数（L77-L81）处理 Pandas Series 可能嵌套返回单元素数组的问题。

3. **`__getitem__()` 方法**（L144-L210）— **核心 tokenization 流程**：
   
   **Step 1 — Chat Template 应用**：
   ```python
   prompt_chat = [{"role": "user", "content": prompt}]
   prompt_chat_str = tokenizer.apply_chat_template(
       prompt_chat, add_generation_prompt=True, tokenize=False
   )
   response_chat_str = response + tokenizer.eos_token
   ```
   
   **Step 2 — 分别 tokenize**：
   ```python
   prompt_ids = tokenizer(prompt_chat_str, ...)["input_ids"][0]
   response_ids = tokenizer(response_chat_str, ...)["input_ids"][0]
   ```
   
   **Step 3 — 拼接**：
   ```python
   input_ids = torch.cat((prompt_ids, response_ids), dim=-1)
   ```
   
   **Step 4 — 填充/截断到 max_length**：
   - 序列短于 max_length → 用 PAD token 填充
   - 序列长于 max_length → 按 truncation 策略截断（left: 保留末尾 / right: 保留开头）
   
   **Step 5 — 生成 position_ids**：
   ```python
   position_ids = compute_position_id_with_mask(attention_mask)
   ```
   
   **Step 6 — 生成 loss_mask**：
   ```python
   loss_mask = attention_mask.clone()
   loss_mask[:min(prompt_length, loss_mask.size(0)) - 1] = 0  # prompt 部分 mask 掉
   loss_mask[min(prompt_length + response_length, loss_mask.size(0)) - 1] = 0  # 最后一个 token mask 掉
   ```
   **关键设计**：`loss_mask` 中只有 response 部分的 token 为 1（最后一个除外），prompt 部分的 token 为 0，这样在计算交叉熵损失时只对模型需要学习的 response 部分计算 loss。

- 导入 `verl.utils` — `hf_tokenizer`

## 6. 常量定义层

### 6.1 [kernel/constant.py](file:///c:/lzq/分享/KernelGYM/drkernel/kernel/constant.py) (119 行)

**文件功能描述**：存放 Qwen3 模型的专用 Chat Template 字符串常量（Jinja2 模板格式）。该模板支持 tool_call 格式的输出，适用于 multi-turn agent 交互场景。

**核心常量**：

| 常量 | 类型 | 含义 |
|------|------|------|
| `QWEN3CHATTEMPLATE` | `str` (Jinja2) | Qwen3 模型的专用 Chat Template，支持工具调用格式 `<tool_call>...</tool_call>` |

**模板关键组成部分**：
1. **系统消息处理**：解析 `system` 角色的消息，支持 `tools` 列表的渲染
2. **工具声明渲染**：`<tools>` → `<function>` → `<name>`, `<description>`, `<parameters>` ，支持嵌套参数结构
3. **工具调用响应格式**：`<tool_call><function=name><parameter=key>value</parameter></function></tool_call>`
4. **消息循环处理**：
   - `assistant` 角色带 `tool_calls` → 渲染为 `<tool_call>` 格式
   - `user`/`system`/`assistant` 普通消息 → 标准 `<|im_start|>role\ncontent<|im_end|>` 格式
   - `tool` 角色 → 渲染为 `<tool_response>` 格式，连续的 tool 消息合并到一个 user 块
5. **生成提示**：若 `add_generation_prompt=True`，追加 `<|im_start|>assistant\n`

**与其他文件的依赖关系**：
- 被 [kernel/fsdp_sft_trainer.py](file:///c:/lzq/分享/KernelGYM/drkernel/kernel/fsdp_sft_trainer.py) 和 [verl_patch/trainer/code/fsdp_sft_trainer.py](file:///c:/lzq/分享/KernelGYM/drkernel/verl_patch/trainer/code/fsdp_sft_trainer.py) 导入
